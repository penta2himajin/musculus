# 盲検 A/B:長さを考慮したグルーピング(SBV2)

前回の A/B(1 パス vs 文ごと分割)は **3 勝 2 敗・平均 CMOS ちょうど 0.00** でした:

- 長文・複数文では分割が息切れを減らす(+2, +2)
- 短文では分割が流れを壊す(−3)、分割側に脱音・過大な下降も出た

そこで**中間案**を実装しました:短い文は連結し、**1 グループが `--max-chars` を超えたら区切る**([src/segmenter.rs](../../src/segmenter.rs) の `group_sentences`)。このセットは **1 パス vs グルーピング(40 文字)** を比べます。

## ファイル構成

```
listening/04-sbv2-whole-vs-grouping/
  pair-01/A.wav  B.wav   ← 同じ文・同じエンジン、片方は 1 パス、片方はグルーピング
  ...(全 5 ペア)
  key.ndjson             ← どちらがグルーピングか + ペア種別(採点まで開かない)
  score-sheet.md
```

## 比較条件

- **同一エンジン(SBV2JE / tsukuyomi)、同一テキスト**、違いはグルーピングの有無のみ
- 両側とも 48 kHz モノラル、**−20 LUFS に一致**(全ペア達成値を検証済み)
- グルーピング側は区切りが入った分だけ無音(0.4 秒)が挿入されます

## このセットの設計上の特徴

| 種別 | ペア | 意味 |
|---|---|---|
| **signal**(3 ペア) | pair-01, 02, 03 | 実際に区切りが入ったペア(2 セグメント)。グルーピングの効果そのものを測る |
| **control**(2 ペア) | pair-04, 05 | `--max-chars` 以内に収まり**グルーピングが 1 パスと同じ経路**になるペア。**介入が無いので、ここで差を感じたらそれは雑音** |

**control を入れている理由**:この合成器は**非決定的**です(同一モードで合成しても波形が一致しないことを実測:`md5` が異なる)。差の出ないはずのペアでどれだけ差を感じるかが、判定の信頼性の尺度になります。

**実測メモ**:区切りを入れると音声は**短くなりがち**です(例:pair-01 は +0.4 秒の無音を挿入しても全体は +0.06 秒しか伸びない)。1 文ずつ合成すると文をまたぐ連続性が失われ、合計の発話時間が縮むためで、これ自体が聴感に影響しうる差です。

## 聴き方

1. ペアごとに A → B(順序を変えて 2 回聴くと確かです)
2. 見るところ:
   - **息切れ**(長文で改善しているか)
   - **短文の流れ**(前回分割で壊れた点が回復しているか)
   - 区切りの**無音 0.4 秒**が長すぎ/短すぎないか
   - 文末の収まり・語尾の脱音
3. 判定:どちらが自然か、差の大きさ(CMOS −3〜+3)、気づいた点

## 判定の意味

- **signal でグルーピングが勝ち、control で差がない** → グルーピングを CLI の既定に採用(`--split-sentences --max-chars N` を既定化)、`N` を調整
- **signal でも差がない/1 パスが良い** → 長文の息切れはセグメンテーションでは説明できず、別要因(スタイル・sdp_ratio)へ
- **control で差を感じた** → 判定の分解能がその程度なので、その前提で結果を解釈します(雑音の大きさの実測値として記録)
