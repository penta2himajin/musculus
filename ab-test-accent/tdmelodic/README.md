# 聴き比べ:複合語のアクセント(tdmelodic vs 現在のフロントエンド)

**同じ語・同じ声・同じ音量**で、**アクセントの付け方だけ**が違う 2 テイクです。どちらが自然かを 1 人で判定するためのセットです(左右どちらがどちらの方式かは伏せてあります)。

## 対象語(5 語)

`01`〜`05` がそれぞれ 1 語です。これらは **tdmelodic(UniDic+ニューラル推定)と現在のフロントエンド(OpenJTalk/NAIST-jdic)でアクセント位置が食い違った語**です(40 語の自動比較で 31 一致 / 8 不一致、そのうち 5 語を選抜)。

| ペア | 語 |
|---|---|
| 01 | 個人情報保護 |
| 02 | 働き方改革 |
| 03 | 地球温暖化 |
| 04 | 感染症対策 |
| 05 | 教師なし学習 |

## 聴き方

1. ペアごとに `A.wav` → `B.wav` を聴く(順序を変えて 2 回聴くと確かです)
2. 判定:
   - **好ましい方**: A / B / 同等
   - **CMOS(−3〜+3)**: 好ましい方の自然さの差
   - **気づいた点**: アクセントの位置(どこで下がるか)、平板に聞こえるか、など
3. `05` は「教師なし学習」= 複合の切り方が難しい語です

## 記入(採点シート)

[score-sheet.md](score-sheet.md) に記入してください。集計後、対応表(どちらが tdmelodic か)を開示して結果を docs に記録します。

## 判定の意味

- **tdmelodic 側が良い** → 複合語のアクセントは生成辞書で改善できる → 対象語彙を広げて辞書を生成する価値が確定
- **現在側が良い** → フロントエンドの複合語処理は十分で、tdmelodic 経路は不要(この標本では)
- **語によって違う** → 語彙ごとに選択できる仕組み(生成辞書 + 上書き表)が正解

いずれの場合も、**判定がそのまま次の実装判断**になります。
