# 主観聴取ログ(Informal Listening Log)

M4 の自分用 CMOS プロトコル(docs/evaluation.md §5)に至るまでの、非公式な聴取観察を時系列で記録する。定性メモであり、ベンチマーク JSON とは別物。エントリは日付順、追記のみ。

## 2026-09-13 — 第 0 回: M1 の最初の聴取

- **条件**: tsukuyomi(JP-Extra, style 0)、`out.wav` = 「こんにちは、musculus の世界へようこそ。今日はいい天気ですね。」
- **観察**:
  - "musculus" が「エムユーエスシーユーエルユーエス」と**文字読み**になった。ASCII ラテン文字列が NJD 辞書で英字読みに展開されるため。ローカル ja TTS の既知の挙動
  - **それ以外は驚くほど自然** — 抑揚・間・読みの正確さ(日本語部分)は実用域
- **検証**(`out-kana.wav`): 「ムスクルス」とカナで書くと自然に発音される → 問題は**音声モデルではなく読みの展開(フロントエンド)**にある
- **帰結**:
  1. M3 の辞書層(euhadra の TermDictionary の鏡像)の最初のユースケースが確定:`musculus → ムスクルス` のようなユーザ所有辞書
  2. ラウンドトリップ CER(M2)の文セットに「英単語混じり文」カテゴリを入れる価値が実測で裏付けられた
- **判定**: 品質の主観基準は期待以上。M4(Irodori 比較)に進む土台として十分

## 2026-09-13 — 第 1 回: 辞書層による文字読み問題の解消

- **条件**: `out-dict.wav` — 「こんにちは、musculus の世界へようこそ。」を `--dict`(fixture: musculus → ムスクルス)で合成
- **観察**:
  - CLI が `dict: "musculus" -> "ムスクルス"` の補正を stderr に報告
  - "ムスクルス" が自然に発音される(M1 第 0 回の文字読み問題が解消)
  - L3 数値でも裏取り:非 gap 14/14 を維持したまま latin-letters ギャップが閉じ(14/22 → 15/22)
- **判定**: ユーザ辞書の体感効果を実測で確認。造語・固有名詞が多い用途では辞書が安定性の本体になり得る

## 2026-09-13 — 第 2 回: JaNormalizer による記号・日付の安定化(実測ベース)

- **数値**: CER reading 0.050 → 0.035 / L3 21/22(辞書併用 22/22)
- **観察**:
  - 「成功率は5%上がりました」が 5%→5パーセント で完全解決(CER 0.192→0.000)
  - 「駅まで50mほどです」は 50メートル と正しく発音される(ASR も メートル と聞き取った)
  - 日付の reading CER 0.018 の残りは物差し側の書き起こし規約(聞こえた ねん/がつ を 年/月 の漢字で書き、NJD が とし/つき と読む)であり、合成側の欠陥ではない
- **帰結**: worklist の実害項目はすべて正規化層で閉じた。残る体感の不安定要素はユーザ語彙(辞書)のみ

## 2026-09-13 — 第 3 回: 月の読みの規則(ユーザの耳 → 組込み規則)

- **指摘**: 「9月」が「きゅうがつ」になるのは微妙(一般には「くがつ」)。「4月」も「しがつ」が自然。「7月」は微妙なところだが、一旦「しちがつ」に揃える判断
- **対応**: JaNormalizer に月の読み規則を追加(シガツ/シチガツ/クガツ)。なお NJD は書かれた「しち」を数詞として「なな」に再マップすることが実測で判明したため、書き下ろしはカタカナで行う
- **設計**: なながつ を好む場合はユーザ辞書(`7月 → なながつ`)で上書きできる(辞書は JaNormalizer より先に走る)
- **数値**: L3 に month 3 項目を追加し gate 強制 → 24/25(辞書併用 25/25)
- **帰結**: 「ユーザの耳 → gold → 組込み規則」という改善ループが回り始めた

## 2026-09-13 — 第 4 回: M1 の聴取(方向性判定)

- **条件**: `out-irodori-long.wav`(Irodori 合成)を news-dict-v2.wav(SBV2 同文)と比較。声は SBV2 出力の参照音声(ゼロショット・クローン)

- **欠点**: 造語 "Irodori" が「あいどしろり」に崩れる — Irodori の既知弱点(漢字・ラテン読みが弱い)の実音響確認。SBV2 側も "musculus" を文字読みしており、両エンジンとも固有語彙が苦手

## 2026-09-13 — 第 5 回: 盲検 A/B の結果(5 ペア)

- **条件**: 同一テキスト・同一参照音声、ペアごとに A/B ランダム(3:2)、両側 48 kHz/−16 LUFS 統一。`listening/01-engine-vs-engine/`
- **結果**: **Irodori 選好 5/5、平均 CMOS +2.75**(採点済み 4 ペア、SBV2 有利は 0)
- **定性的発見**:
  1. SBV2 に「息切れしたような発声」が 5 サンプル中 2 回(pair-03 A、pair-04 B)。Irodori は 0
  2. SBV2 のピッチアクセント誤り(「せんに→ひゃく」/ 期待は「せんに↑ひゃく」)。**L3 は音素のみでアクセントを測っていない** — 評価系の穴として記録
- **判定**: 第 4 回の非盲聴の方向性(Irodori 優位)が盲検で確定した
- **残る gate**: リアルタイム性(CPU RTF 5.29 → CoreML EP 未測定)、造語の辞書配線(Irodori 側は未接続)

## 2026-09-14 — 第 6 回: 低ステップ品質の盲検 A/B(5 vs 40 steps)

- **条件**: 同一エンジン(Irodori)・同一 seed・同一テキスト、steps のみ 5 と 40。48 kHz・**−20 LUFS ペア単位一致を検証済み**、A/B ランダム、5 ペア
- **結果**: **40 steps が 5/5、平均 CMOS −2.80**(5 steps 有利は 0)。長文(12.7 秒)でも差が開いた
- **定性所見**: 5 steps 側は「掠れたような、質の悪いマイクとレコーダーで録ったような音。キンキン響いて不快」(pair-01)
- **判定**: **低ステップ高速モードは不採用**。実時間性(RTF 0.83)は満たすが知覚品質が明確に劣る → 二本立て維持(即応=SBV2、品質=Irodori 40 steps)
- **含意**: 文境界ハンドオフ(第 5 回まで残していた案)はリアルタイム品質ミックスとしては不成立(40 steps の backlog が追いつかない)。高速な品質エンジンが要るならサンプラ変更・fp16・v4.1-Small が候補
- **方法的注意**: A/B を提示する前にラウドネス一致を検証する手順が必須だと分かった(初回生成は −16 LUFS 目標でリミッタが作動し 3.6 dB ずれていた)。`scripts/make_ab_test_steps.sh` が毎回検証する

## 2026-09-14 — 第 7 回: 文分割 + 文間無音の盲検 A/B

- **条件**: SBV2JE、同一テキスト、片方は 1 パス、片方は文分割 + 0.4 秒無音。48 kHz・−20 LUFS を全ペア一致検証済み、A/B ランダム、5 ペア
- **結果**: **split 3 勝 2 敗、平均 CMOS ±0.00**
  - 長文・複数文(pair-01, 02)= split が +2、**息切れが減った** → 仮説は方向として支持
  - 短文(pair-03)= **whole が +3 で明確に良い**、分割は文をまたぐ流れを壊す
  - 分割側の新たな劣化: 脱音(「明日」の「た」)、過大な文末下降(「です」)
- **判定**: 「常に分割」は品質を上げない(正味ゼロ)。**CLI の既定は 1 パスのまま**、`--split-sentences` は opt-in
- **次の一手**: **長さを考慮したグルーピング**(短文は連結し、長文だけ分割)を実装して、1 パス・常時分割と三点比較する。無音長も同時に詰める

## 2026-09-14 — 第 8 回: 長さ考慮グルーピングの盲検 A/B(signal 3 / control 2)

- **条件**: SBV2JE、同一テキスト、1 パス vs グルーピング(40 文字まで連結・区切りに 0.4 秒無音)。48 kHz・−20 LUFS を全ペア検証済み、A/B ランダム。**介入が無い対照ペアを 2 つ混入**
- **結果**:
  - signal 3 ペア:**group 1 勝 2 分 0 敗**(最長の pair-01 で +2、他は同等)
  - control 2 ペア:**±1**(方向は両側)
- **判定**: グルーピングは**有害ではない**が、利得は「長い文脈の息切れ」に限定的。**既定は 1 パスのまま**、長文向け推奨オプションとして文書化
- **方法論の収穫**: **合成が非決定的**なため、介入の無い対照ペアでも 1 CMOS 程度の差が生じる。つまり **±1 は判定の分解能以下**で、+2 が辛うじて有意。対照ペアを入れる設計が効いた
- **副産物**: 「先週と比べると」のアクセント不自然(pair-04、control 側での指摘)= グルーピングとは無関係のフロントエンド/モデル課題。期待形として「先週と比べると(HHHMLMMMMM)」というメモ(M=中程度の高さ)が得られたが、**現行の素性は H/L の 2 値**なので M は表現できない
- **次の一手**: 長文特化の追試(長いナレーション 5 本)で +2 の再現を確認 → 既定切り替えを判断。アクセントは特殊拍のトーン継承の修正へ

## 2026-09-14 — 第 9 回: 丁寧接頭辞 お/ご のアクセント修正(gift-fix A/B)

- **背景**: 「ご注文は」の発音がおかしく、数詞の判定に集中できないという指摘 → 先に修正
- **原因**: 参照実装(OpenJTalk)は接頭辞「ご」に acc=2 を付け、句の 2 モーラ目(チュ)の後で下降させる(ゴL チュH ウL モL ンL ワL)。辞書は **注文 = 0/4(平板)**、規範も「接頭辞お/ごは結合相手のアクセントを変えない」([大修館](https://www.taishukan.co.jp/kokugo/media/blog/?act=detail&id=545)、[注文 [0]](https://mojimori.app/ja/words/chuumon))→ **参照実装が外れ値**
- **修正**: 逸脱層 規則1(お/ご + 平板名詞 → 接頭辞のアクセントを 0)。ご注文は `LHLLLL` → **`LHHHHH`**(ゴL + チュウモンハ全て高)
- **A/B**(48 kHz / −20 LUFS 統一、`gift-fix-a` = 参照、`gift-fix-b` = 接頭辞規則 + 上書き表):
  - **listener 判定: 「b はかなり自然で良い」** → **接頭辞規則を既定 ON に昇格**(`--no-accent-deviations` で参照忠実に戻せる)
  - 同時に提示した 1,200円(`LLLHH`)を含めて自然と評価 → 上書き表の形がこの文では妥当
- **含意**: お/ご + 平板名詞は数詞よりはるかに頻出のクラスで、実害の本命だった。数詞の句レベル制御(HH 形)は優先度を下げつつ、上書き表で個別に対応

## 2026-09-14 — 第 10 回: 盲検セットによる句頭の検証(セL vs セH)

- **条件**: `listening/07-blind-shinshuu/` の 6 テイク(中立名 A〜F・順序ランダム・**全テイク −20.00 LUFS 一致**・README と採点シートに音調の記述なし・対応表は伏せた)。同じ文「先週と比べると」、違いはピッチのみ
- **listener 判定: C か F が良い** → 対応表を開くと **C(候補5)= セH + 全H**、**F(候補6)= セH + 連続H + 文末トL** で、**どちらも句頭が高い(セH)**
- **重要な意味**: 直前に明示選択した **D(候補3)= セL** とは句頭が逆。**盲検で比べると高起が好まれた** = 明示選択が盲検で覆った初の例
- **文献との整合**: 句頭の上昇(initial lowering)は、句頭モーラがアクセント核を持つ/重音節のとき抑制され、minor phrase 境界では上昇が弱まる。listener 自身の「二千二百円」の実発音(ニH)とも同現象
- **登録**: **F(セH + 連続H + 文末トL)** を採用。上書き表は合成エントリ(`センシュウト → HHHHH`、`クラベルト → HHHHL`)で表現し、`expected_tones = HHHHHHHHHL` として宣言
- **未了**: 知人による第三者評価を募集中(採点シート回収後に集計 → 必要なら再切替)
