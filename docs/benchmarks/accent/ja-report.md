# L3 アクセント・レポート(ja)

フロントエンドが **実際に decode へ渡している mora 単位の H/L** を一覧する。音素レベルの L3 gate はピッチの誤りを見逃すため(「せんに→ひゃく」の実例、docs/evaluation.md §3.4)、この粒度で測る必要がある。

生成: `cargo run --release --features onnx --example accent_report`
(アノテーション: `tests/evaluation/annotations/ja_accent.jsonl` に `expected_tones` を記入すると、以後は一致チェックになり、CI gate にできる)

| 入力 | カナ | tones(H/L) | 期待(要記入) |
|---|---|---|---|
| `1,200` | センニヒャク | `HLLHH` |  |
| `1,200円` | センニヒャクエン | `HLLHHLL` |  |

## 読み方と注意

- `tones` は 1 文字 = 1 モーラ、`H`=高 / `L`=低。句読点はトーンを持たないため含まれない
- この H/L は VITS2 decode に渡る**アクセント素性**であり、音響的な F0 そのものではない
- したがって二段構えで見る必要がある:
  1. **素性の誤り**(フロントエンド/アクセント推定の問題)→ このレポートで検出でき、修正は正規化層・辞書・アクセント規則の仕事
  2. **実現の誤り**(素性は正しいが音が平坦)→ このレポートでは検出できず、音響測定(F0 抽出)か聴取が必要
- 期待値を記入する際は「その語を単独で読んだときの自然な型」を基準にする(文脈依存の型は文単位で登録する)

## 既知の欠陥:1,200 の セ/ン(2026-09-14、native speaker のアノテーションで確定)

native speaker の知見:**`1,200` の H/L は `HHLHH`(前置きあり)または `LLLHH`(文頭)で、いずれの場合も「セン」の 2 モーラは同じトーンになる**(手前に文章があるかどうかで HH か LL が変わる)。

現状の素性は **`HLLHH`** — セ=H なのに ン=L で、**どちらの許容形にも反する**。整列表示で確認:

```
[NG] 1,200 | カナ センニヒャク | tones HLLHH | expected LLLHH
            セH ンL ニL ヒャH クH
```

- 末尾(ニL ヒャH クH)は両許容形と一致しているので、欠陥は**セ/ンの 2 モーラに限定**される
- 文脈依存も同様にずれている(「ご注文は1,200円です」でも セ=H, ン=L)
- **原因の候補**:撥音(ン)・促音(ッ)・長音(ー)は**特殊拍**でアクセント核にならないため、直前のモーラと同じトーンになるべきだが、現行の素性生成はその規則を課していない。`[`/`]`(アクセント句の高低ステップ)が セ と ン の間に入っている疑い
- **文頭が H で始まる点**も第二の論点:文頭(前置きなし)は `LLLHH` なので、句頭が H になっている

### 次の一手(アクセント)

1. **特殊拍のトーン継承**を規則として入れる(直前のモーラと同じトーンにする)→ `HLLHH` は `HHLHH` になるはず(前置きありの形と一致)
2. 残る**句頭の高低**(文頭 vs 文中)を調べる — ここが合えば `LLLHH` も出る
3. 上記は素性側の修正。**実現側(F0)の確認**も並行して価値がある(素性が正しくなった後、実際に音が上がっているか)
- 期待値の記入後、`cargo run --release --features onnx --example accent_report` が不一致で非ゼロ終了するので、CI の gate に組み込める

## 次の一手

- native speaker(あなた)が `expected_tones` を埋める → 一致チェックが gate 化
- 1,200 については **F0 を実測**して素性(H/L)と比較する:素性どおりに上がっていれば「読みは正しく、聞こえの問題」、上がっていなければ「実現側の欠陥」と切り分けられる

## 素性表現の限界(2026-09-14、追加所見)

listener が「先週と比べると」の自然形を **`HHHMLMMMMM`**(M = 中程度の高さ)と記述した。しかし **現行の素性はモーラごとの H/L 2 値**(VITS2 decode に渡るアクセント素性)であり、**M のような中間レベルは表現できない**。

- 含意 1:素性が正しくても、自然な日本語の緩やかな F0 変化は**モデルの実現側**が担う。したがって素性の一致は音の自然さの必要条件であって十分条件ではない
- 含意 2:このレポートで `ok` になった項目でも、聴感上の不自然さが残る可能性がある。最終判定は聴取(F0 実測を併用)
- 運用:アノテーションは H/L に丸めて記入し、M の情報は `note` に残す(上記の例のように)

## 研究調査(2026-09-14): 数詞のアクセントは「複合語アクセント規則」の問題

listener の指摘「**千円は セH ンL で正しいが、千二百円ではそうならない**」は、数詞を含む複合語のアクセントという既知の研究領域に一致する。調査結果:

### 1. 左優勢(left-dominant)アクセント — 記憶されていた研究はこれ

[**Left-dominant Accentuation: The Case of Sino-Japanese Numeral Compounds**](https://doi.org/10.15083/00016465)(東京大学学術機関リポジトリ)

- 従来の複合語アクセント論は「**右優勢**(後部要素 N2 がアクセントを決める)」が主流(Kubozono 1997, Tanaka 2004 ほか)
- しかし**数詞を前部要素(N1)に持つ複合語はこの規則で説明できない**。数詞の場合、**N1 のアクセントが保持される**(=左優勢)と主張する論文
- 例:熟語(アクセントなし)になるはずの「一語」が「イチ＼ゴ」とアクセントを持つ、など
- **重要な制約**:「**非母音モーラ(特殊拍)はアクセント核になれない**」(PK-PROM)。アクセント核が促音化したモーラに来る場合は核が移動する

→ **千円 = セH ンL はこの制約と整合**(核が セ にあり、特殊拍の ン は核になれないので後ろに下がる=H L)。つまり**我々のトーン生成は千円については正しく、欠陥はアクセント推定側**という診断を裏付ける

### 2. 一般の複合語アクセント規則(後部要素の長さで決まる)

[**日本語複合語のアクセント付与規則**](http://hdl.handle.net/2115/45656)(北海道大学)

- 後部要素が **5 拍以上**:前部要素は平板化し、後部要素の元のアクセントを保持
- 後部要素が **3〜4 拍**:前部要素は平板化し、**後部要素の第 1 拍に核**
- 後部要素が **1〜2 拍**:別規則(窪薗・山本 1999 の a/b/c)

→ 「千二百」= セン(2 拍)+ ニヒャク(3 拍)では「**前部 セン が平板化**」する側の規則が働く。listener の期待(セ ン が同一トーン)と方向が一致する

[**Kubozono & Mester, Japanese compound accent (foot-based)**](https://people.ucsc.edu/~mester/papers/1995_kubozono_mester_japanese_compound_accent.pdf) はこれを韻脚(foot)単位で一般化:1〜2 韻脚の後部要素では「**penultimate foot に複合アクセント**」、3 韻脚(overlong)では後部要素のアクセントが保持される

### 3. 実務の権威: NHK の扱い

[**「数詞＋助数詞」の発音とアクセント**](https://www.nhk.or.jp/bunken/research/kotoba/pdf/20160901_5.pdf)(NHK 放送文化研究所)

- 数詞+「円」のアクセントは伝統的に不規則(1/2/3/6/8 円=平板、4/5/9 円=頭高、7 円=中高)
- 『NHK日本語発音アクセント新辞典』(2016)は**「円」の前で落ちる型へ単純化**する方向を採り、平板型を第 2 アクセントとして併記
- 数詞+助数詞の読み(4=ヨ/ヨン、7=ナナ)とアクセントを 258 助数詞について整理した研究もある([KCI 2021](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002793674))

### 4. TTS 側の最先端

[**Phonetic and Prosodic Information Estimation from Texts for Genuine Japanese End-to-End TTS**](https://www.isca-archive.org/interspeech_2021/kakegawa21_interspeech.pdf)(Interspeech 2021)

- 日本語 TTS の最大の難所は「**アクセント核を適切な位置に置くこと**」であり、従来は規則・辞書依存
- 文字単位の NMT(Transformer)で音素・プロソディを推定し、**手作業アノテーション 5,142 文で PPI 95.0% 精度**
- つまり「辞書・規則では数詞のような文脈依存ケースを捉えきれない」という我々の問題意識は研究でも共有されており、**ニューラル PPI 推定が長期的な解**

## この調査を踏まえた修正方針(改訂)

| 案 | 内容 | コスト | 位置づけ |
|---|---|---|---|
| **A. アクセント上書き表**(ユーザ所有) | 「センニヒャク」→ 平板 等を指定。用語辞書と同じ「ユーザが語彙を持つ」思想 | 小 | **まずこれ**。観測済みケースを即修正でき、検証器(accent_report)も既にある |
| **B. 数詞複合語のアクセント規則** | 左優勢+後部要素長の規則を実装し、数詞+助数詞のアクセントを自動推定 | 中 | A の後。**規則ごとに A/B と聴取で検証**が必要(規則は方言・世代差あり) |
| **C. ニューラル PPI 推定** | NMT でアクセント核を推定(研究水準) | 大 | 長期。モデル・学習データ・ONNX 化が必要 |

**現時点の結論**:我々のトーン生成は「特殊拍は核になれない」制約を含め**千円では正しい**。欠陥は**数詞複合語のアクセント推定**にあり、まず **A(上書き表)** で実害を止め、**B** を研究知見(左優勢・後部要素長)に沿って段階的に実装し、各段階を聴取で検証するのが妥当。
