# ADR-0004: M4 スパイクの結果と実装継続の判断

- ステータス: 採用(実装継続)
- 日付: 2026-09-13
- 関連: ADR-0002(Irodori を比較候補とする), docs/benchmarks/irodori-rtf/baseline.json

## 背景

ADR-0002 で Irodori-TTS を「測ってから採否する」比較候補とした。M4 Step A として、
公式 WebGPU エクスポート([noguchis/irodori-tts-onnx](https://huggingface.co/noguchis/irodori-tts-onnx)、
ビット忠実検証済み corr=1.0 の参照ランタイムを Rust に移植)を用いた **RTF スパイク**を実施した。

## 実測結果(Apple M1 Max, release, CPU EP, 40 Euler steps)

| 項目 | Irodori(v3) | SBV2JE(対照) |
|---|---|---|
| RTF | **5.29**(1.36 秒音声に 7.19 秒) | 0.199 |
| ロード | 3.47 秒 | 2.35 秒 |

- 等価 DiT 前向き回数 ≈ 80(20 steps × 3 分岐 CFG + 20 steps 単独)
- RTF は steps に線形 → 20 steps で ~2.6 に半減(品質は再測定要)
- **未達**: 双方向音声のエンドゲーム(リアルタイム応答)には CPU RTF < 1.0 が必要で、現状未達。最大のレバーは **CoreML EP**(Apple GPU/ANE)で未測定

## 判断: 実装を継続する

1. **音質の比較はまだ誰も行っていない**。ADR-0002 の原則(未検証のものは測ってから採否)どおり、次は聴取(CMOS)で SBV2 と並べる。RTF 5.29 はバッチ用途では許容内で、音質比較の障害にならない
2. **ライセンスが完全にきれい**(MIT + Apache-2.0)であることが実装後に確認され、SBV2 系のキャラ規約より配布面が明瞭
3. 参照音声を **SBV2 tsukuyomi の出力**にすることで、両エンジンが同じ声で比較できる構造を実証済み(ゼロショット・クローン経路の動作確認も兼ねる)
4. RTF は測定済みの改善経路(CoreML/steps 削減)があり、「CPU で遅い」ことは採否の否決理由にならない — **バッチ品質の比較を先に**行う

## 次の測定(M4 継続条件)

- あなたの耳による盲検 CMOS(同じ声・同じテキスト、順序ランダム、−3〜+3)→ 品質判定
- round-trip CER + UTMOS の客観裏付け
- CoreML EP 有効時の RTF 再測定 → リアルタイム性の判断
- これらの結果で、ja の第二アダプタとして正式採用するかを新 ADR に記録する

## 意思決定

「測れ、憶測するな」の原則どおり、RTF 5.29 という実測値があっても音質は未測定であり、
未測定のまま採否しない。実装・測定基盤を継続する。
